# pi-agent-core 架构解读

一个 agent 循环，被做成一个库。

这本书从代码出发，讲清楚 `@earendil-works/pi-agent-core` 是怎么搭起来的：它承诺什么、拒绝什么、支点在哪里。

> **基线：commit `cd20a8d2e`（main，v0.83.0+219）**
>
> 全书对应 pi 仓库 main 分支上的这个提交。代码引用写成 `文件:行号`，路径相对于 `packages/agent/`。行号会随代码演进漂移，以文件内容为准。

## 读者假设

你会读 TypeScript，知道 LLM API 的基本概念（messages、tool calls、streaming），不需要事先了解 pi 仓库。

## 组织方式

**整体 → 局部 → 横切。**

第一部分建立对整个系统的正确认知，不碰实现细节。第二部分逐个部件展开，顺序是依赖顺序——每章只依赖它前面的章。第三部分处理那些不属于任何单一部件的问题。

## 体例

正文只讲从代码里能读出来的东西。代码引用统一写成 `文件:行号`，并且**每一个 `文件:行号` 引用都就地附上对应的代码引文**——读者不需要打开编辑器就能核对任何一处引用。引文可以删减，以 `// ...` 标出省略处；删掉的是重复模式，保留的是论据本身。需要完整上下文时再按行号回仓库看。引文里出现 `this` 时，头注释必须声明宿主类型——写成 `（Agent.createLoopConfig 内）` 而不是 `（createLoopConfig 内）`；只写函数名，读者看不出 `this` 是谁。

正文之外，书里有三种反复出现的卡片组件：

- **插叙**（`###` 级，章内）：补一块读者可能缺、但与 pi 无关的背景知识——平台 API 模式、LLM 消息结构。跳读不影响主线。
- **岔路**（`###` 级，章内）：主干引文里折叠掉的自包含旁支，在这里展开。它是主线的一部分，只是位置被推迟。岔路容得下超出本章平均难度的内容——正因为它可跳过，密度超标的段落应该进岔路而不是稀释进主干；难度超标时要在开头向读者承认这一点，并给一张逐层展开的地图。承认难度时语气可以放松（游戏化比喻也行），别写成教科书式的免责声明。
- **为什么不去**（章末）：用仓库里的设计文档或 git 历史回答"这里为什么不写得更简单一点"。它是脚注，不是主线；没有可靠出处的章节不放。

## 范围之外

- `packages/ai` 的内部实现（provider 目录、模型元数据）——本书只把它当作"实现了 `StreamFn` 契约的下游"。
- `packages/tui`、`packages/coding-agent`——它们是本库的消费者，不是本书的主角。
- `docs/harness.md`（v1 设计文档）已被仓库明确废弃，只在历史脚注中出现。
