# π-agent book 预览站设计系统

这份文档沉淀 `web/` 预览站（Vite + Vue 3）的视觉与交互规范。两条原约束来自立项时的一句话：

- **圆**：pi-agent 的名字里有 π，全站的几何语言都从圆派生。
- **极简**：pi 的架构本身简单克制，网页必须同样克制——每加一个元素都要能对号入座。

---

## 1. 设计原点

全站只有**一个形状**（圆）、**一个彩色**（π 蓝）。所有装饰、层级、状态都从这两个资源里推导，不引入第三个词汇。

- 圆承担三种语义：**层级**（标题/目录记号）、**进度**（表盘、首页 hover 弧）、**装饰**（首页轨道环）。
- 蓝色只标记"活的"东西：当前位置、可交互态、强调。静态装饰永远是墨色或灰。

## 2. 设计令牌

定义于 `src/style.css` 的 `:root`：

| 令牌 | 值 | 用途 |
|---|---|---|
| `--ink` | `#111114` | 正文标题、强边框 |
| `--ink-soft` | `#55555c` | 次级文字 |
| `--ink-faint` | `#9a9aa2` | 三级文字、静默图标 |
| `--paper` | `#fbfbf9` | 页面底色（暖白） |
| `--line` | `#e4e4de` | 分隔线、静态环 |
| `--accent` | `#1d4fd7` | π 蓝，唯一彩色 |
| `--accent-soft` | `rgba(29,79,215,.08)` | 行内代码底色 |
| `--radius` | `999px` | 全圆角（胶囊/圆） |
| `--mono` / `--sans` / `--serif` | SF Mono… / Inter+PingFang… / Source Han Serif+宋体… | 代码 / 正文 / 标题 |

排版基调：正文 16px / 行高 1.85，阅读栏 `max-width: 720px` 居中。标题用衬线（书感），正文用无衬线，代码用等宽——三套字体各司其职，不混用。

## 3. 圆词汇表：层级即圆的分数

这是全站最核心的规则，**标题层级编码为月相**（圆的分数，π 的字面化）：

| 级别 | 图形 | 含义 |
|---|---|---|
| 章头（h1 位） | 72px 墨环，圆心是章节号，蓝珠沿圆周缓慢公转 | 轨道本身：一整圈 = 一章，蓝珠在环上"跑循环" |
| h2 | 16px 满月——墨盘 + 纸色环形山（SVG） | 满月（2π） |
| h3 | 13px 左半圆盘 | 半月（π） |
| h4 | 12px 蓝色 1/4 扇形 | 弦月（π/2） |

层级向下，月相渐亏；章头在月相之外——它是月亮运行的轨道。左侧悬浮目录（TOC rail）使用**完全相同的词汇**：h2 环形山满月、h3 半盘、h4 扇形，正文和目录可以互相辨认。

### 禁令（都是踩过的坑）

- **实心圆盘必须有"表面细节"才算满月**——纯实心圆（无论蓝墨、无论 20px 还是 16px）会无可避免地读成无序列表的 bullet。h2 的满月用 SVG 在墨盘上挖两个纸色环形山（`FULL_MOON_SVG`，正文 `buildToc` 注入、TOC `v-html` 复用同一字符串），剪影被打破后才读作"月亮"。曾试过纯蓝盘、纯墨盘、柔光渐变盘，全部淘汰；圆+直径线属于几何课语汇，和月相体系不搭，也淘汰。
- **描边环是章头（轨道）的专属语汇**——h2 不得使用任何形式的空心环/带直径线的环，否则与 H1 的 72px 轨道环互相稀释。
- **TOC 记号的 1.5px 描边环用 `#77777e`，不用 `--ink-faint`**——1x 屏上浅灰细环的左边缘会被抗锯齿吃掉。
- **填充形记号不要加 transparent 边框**——gradient 以 padding-box 为原点平铺，会渗进环区导致诡异裁切（"左半边跑到右边去"那次事故）。
- TOC rail 内侧留 8px 富余（`margin-left: -8px` + padding），记号不贴裁切边。

## 4. 布局骨架

```
┌────────────────────────────────────────────┐
│ π PI-AGENT BOOK（顶栏，fixed，指针穿透）      │
│                                            │
│  TOC rail        720px 阅读栏               │
│  （fixed，左侧    章头：kicker + 大环 + 标题   │
│   空白处悬浮）    正文…                      │
│                   章节导航（上一章/下一章）     │
│                        ┌──────────┐        │
│                        │ 钉住视窗栈 │ ◉ 表盘  │
│                        └──────────┘        │
└────────────────────────────────────────────┘
```

- **TOC rail**：`position: fixed`，垂直居中于左空白，`left: max(28px, 50% - 640px)`；视口 < 1240px 时隐藏（没有空白就不硬塞）。当前条目亮起一圈 360° 轨道环（`@property --sweep` 扫一次后常驻），点击平滑滚动——**每一节都是可分享的深链**：地址栏 hash 随滚动经 `replaceState` 同步（不产生历史记录），读者随时可以直接复制当前小节的 URL。
- **表盘 dial**：右下 fixed，64px 圆环，弧长 = 阅读进度（一圈 = 一章），中心衬线章节号；点击回首页。
- **章节导航**：文末细线之上，文字链 + 34px 圆环箭头，hover 圆环染蓝。
- **首页**：四层同心轨道环（两层旋转、一层虚线、一层蓝色弧段），章节条目 hover 时用 `stroke-dashoffset` 画满一圈弧。

## 5. 代码块（全站交互密度最高的组件）

### 视觉

**浅色卡片，不是深色板**（`#f2f2eb` + 1px `--line` + 14px 圆角）。曾做过深色代码块，被否决：深色块打断阅读注意力，代码是书页的一部分，不是嵌入的终端。语法高亮 palette 配套浅色底（keyword 用 π 蓝、string 绿、number 橙、type 青、注释灰斜体）。

### 悬浮展开

- 只有**真实溢出**栏宽的块才响应（`scrollWidth > clientWidth + 2`）；放得下的块悬浮多久都不动。
- 悬浮需**停留 260ms**（`EXPAND_DELAY`）才触发——扫过去不算数，防误触。
- 展开宽度 = 最长行宽，封顶 `100vw - 96px`；同时浮起阴影 + 圆角变大，读作"从页面里拎出来"。
- **动画用实测像素过渡**：`max-content` 不可插值，直接 transition 会瞬间跳变。展开前先把当前宽度写成 px 再过渡到目标 px；中途反向时 `offsetWidth` 读到的是动画中间值，所以回退也是顺滑的。这条是"动画卡卡的"两轮反馈后的最终解法。

### 钉住（pin）

- 每个代码块悬浮时右上角浮出**图钉按钮**（24px 圆形 chip；图标用 Lucide `pin` 原版路径——自绘的"圆+线"怎么画都像放大镜，别重画）。
- 钉住 = 克隆进右上角 fixed 钉栈，多块纵向堆叠。源块保持常显蓝色图钉表示已钉。
- 钉住视窗常态是 **116px 锁孔**：只露头部几行 + 底部 40px 渐隐（"下面还有"的暗示）；悬浮停留 180ms（`PIN_DWELL`）后原地展开为完整代码（宽封顶 `min(52vw, 900px)`，高封顶 72vh）。
- 展开/收起同样走实测像素过渡；**动画结束（transitionend）后才允许出现滚动条**（`.settled`），避免中途 reflow 抖动。
- 章节可通过 `chapters.js` 的 `pin` 字段声明**默认钉住**（如第 2 章的 runLoop 骨架——它是那一章的"路标"）。读者手动取消后会话内记住（`pinDeclined`），不再重新钉上。视口 < 900px 钉栈整体隐藏。

## 6. 引用与出处

- **普通 blockquote**：2px 左竖线 + 灰字，安静退后。不要做成卡片（做错过一次）。
- **"为什么不去"类提问**：渲染后按措辞打上 `is-question`，变成浮起的白卡片 + 蓝色圆环衬线 `?`——它是书的一种固定文体，需要存在感。
- **出处链接**：`a.src-ref` 用蓝色点状下划线（`underline dotted`）；在代码清单的头注释里保持注释的灰色，hover 才变蓝。每个论断都链回 pi 仓库基线 commit 的对应行。

## 7. 动效规约

- 缓动基本统一：`cubic-bezier(0.22, 1, 0.36, 1)`（展开类 0.45–0.5s），状态变色类 0.2–0.3s。
- 入场只有一个 `rise`（24px 上浮 + 淡入，0.7s）。
- 所有"可能出现也可能不出现的控件"（图钉、钉住视窗的 ×）都是 hover 浮现 + `opacity` 过渡，不位移。
- **标题锚点不做浮现**：标题记号本身就是锚点（真实的 `<a>`），hover 时变换月相提示可点——h2 满月自转 120°（环形山位移）、h3 半月翻身 180°、h4 扇区前进 90°。曾用过"标题末尾浮现小圆环"的方案，已废弃（多一个图形词汇，不如让记号自己活起来）；h2 也试过 hover 扫轨道环，因轨道环划归章头专属语汇而弃用。
- hover 触发的**展开类**交互一律带意图延迟（180–260ms），浮现类（纯视觉）不带。

## 8. 文案与语气

- 站点有第 00 章《从这里开始》作为给新读者的"小地图"：语气是带人参观一个地方，不是功能说明书；交互演示（图钉试玩块）嵌在散文里。
- 全站文案遵守同样的克制：短句、不吆喝、不用 emoji。

## 9. 深色模式

- 首次访问跟随系统 `prefers-color-scheme`；手动切换后将明确偏好写入本地存储，后续访问保持选择。
- `<head>` 中的轻量初始化脚本会在应用与样式加载前确定主题，避免先闪出浅色书页；浏览器 `theme-color` 与原生控件配色同步更新。
- 深色仍沿用暖墨纸张、圆与 π 蓝的单一视觉词汇。代码块只是比书页略亮的卡片，通过边框和层级区分，不转译成终端黑板。
- 深色值与组件表面色同样由 `src/style.css` 令牌集中管理；组件内不得另写一套主题选择器。

## 10. 明确不做

- **移动端适配暂缓**——这本书的内容不是能在手机上轻松读完的，视口不足时优雅降级（TOC rail、钉栈隐藏）即可。
